# auto 真实调用、日志体积与往返审查

日期：2026-10-12。状态：auto 本地实现已更新，整体优化仍在进行，未发布。

## 结论

“超过 8 KiB 就只返回目录和少量样例”的初稿不适合作为默认行为。它会让多数 UIA/Intent 观察变成补读，也可能截掉日志后部真正需要的诊断。不能用大量小动作回执或已被模型工具截断的对话结果掩盖这一点。

当前 auto 优先在一个回复内完整交付：保留原形状，或用完全可还原的表格表示重复字段。仍超过整个回包预算时，才提供部分视图。部分视图给出完整记录或较长首尾文本，而非固定 3 条、160 字符；字段事实、原偏移和可执行的原文读取请求同时返回。

## 样本与口径

- 检索原有 1,215 个 Codex 历史文件索引，筛选、关联 13,958 个包含 Bridge 调用的外层工具调用及结果；外层一次调用可以包含多次 Bridge 命令或循环，不能当成设备动作次数。排除当前任务的合成样例。
- 对话中识别 3,581 份命令响应，其中 2,915 份有可完整计量的未提取业务值，来自 133 个会话。未拿到原文的模型侧投影、损坏/截断 JSON、仅有提取结果的返回，不混入原始体积分布。
- 为补齐对话中缺失的大回包，检查 POS 的 docs/tmp 和 Duo 的 output 中 140,471 条 JSON 文件路径。去重后识别 27,667 份响应，其中 25,845 份保留完整未提取的 JSON/text 值。归档由 Duo 兼容性流程主导；77 份 POS 页面树主要来自会员快速创建、报损两个流程。
- 两组来源有重叠，分开统计；不相加冒充独立用户调用数。Cursor transcript 缺少原始 tool_result 的内容不进入字节统计。历史 SDK 的采集范围与截断仍保留。
- 另恢复 186 份完整 logcat 文本，其中 89 份非空。空结果可能来自筛选条件、无 PID 或错误地将 `A|B` 作为字面 grep，不能把空日志当作容量充足的证据。

统计单位为紧凑 JSON 的 UTF-8 字节（1 KiB = 1,024 bytes）。回放走当前公开返回、保存、auto 与 response read 实现；不执行原设备动作。原形状直接比较；表格用独立消费者完整还原后逐字段比较；部分范围与原切片比较。

## 8 KiB 会影响哪些流程

以下为可完整计量的归档业务值，不含回包控制层。

| 类别 | 样本数 | 中位数 KiB | P95 KiB | 超过 8 KiB |
| --- | ---: | ---: | ---: | ---: |
| 全部 | 25,845 | 3.16 | 48.94 | 9,231 / 35.72% |
| UIA 页面观察 | 4,526 | 33.06 | 79.85 | 3,761 / 83.10% |
| Intent | 5,222 | 26.58 | 66.50 | 4,493 / 86.04% |
| POS Native 页面树 | 77 | 105.17 | 171.99 | 71 / 92.21% |
| logcat 归档 | 51 | 1.14 | 73.81 | 18 / 35.29% |

对话恢复出的 89 份非空 logcat，P50 为 637 bytes、P90 为 10,614 bytes、P95 为 18,875 bytes，最大 38,962 bytes。它们更偏向已筛选的小结果；归档里的长日志最大约 240 KiB。两种分布都列出，不能只挑小的一组定阈值。

## 已实现的交付策略

1. 默认完整回包预算仍为 96 KiB；调用者可以用 `output.maxBytes` 选择 16–256 KiB。取消 8 KiB 的部分展示阈值。
2. 超过 32 KiB 的 JSON，如果无损表格能节省至少 30%，就返回完整表格。这个阈值只改变表示，不省略内容，也不要求第二次调用。超预算 JSON 也先尝试完整表示。
3. `aab.response-tables/v1` 保留每个节点、原字段、空值、checked/enabled、顺序、重复文本及完整绑定。常量与 JSON Pointer 列名只写一次；v2 还把多层工作流中完全相同的长诊断文本只存一次，用 `sharedTexts` 的 JSON Pointer 指明每处原位置，先还原文本再展开表格。`partial:false` 表示没有展示丢失，原采集 coverage/truncated 继续有效。中等回包的存储失败也不妨碍完整表示交付。
4. 确实放不下才使用 `aab.response-overview/v1`，在剩余预算里最多提供 64 KiB 的完整记录或首尾文本。数组不截断单条记录，文本优先整行并保持 Unicode 完整。单条巨大的网络正文会给正文片段及状态码等小字段，而不是建议读取一整条超限记录。
5. 保存的原文路径始终不变；select/regex/Script 在原文上执行。补读请求按当前保存数据定页长。没有保存成功就不提供假 ref。已获得所需内容时直接继续，不机械执行 `read`。
