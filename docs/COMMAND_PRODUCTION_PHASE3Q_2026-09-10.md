# 第三阶段 Q：统一执行目标

本批交付是 Intent/Script 的平台目标合同及其完整接线。Android 固定矩阵继续使用 3O 冻结结果，没有重新跑 NotallyX/LocalSend 全套，也没有修改样例业务逻辑。iOS 真机通知仍待用户接入，整体生产验收未完成。

## 已完成

- 平台目标采用显式标签：Android 为 `platform/serial/packageName`，iOS 为 `platform/deviceId/bundleId`，Web 为 `platform/sessionId`。各自连接参数保存在冻结 spec 和哈希中，混用身份、冲突参数、无效端口/URL 在派发前失败。Script 纯代码可以没有目标。
- Script 保留显式跨 App、跨设备调用；`options.target` 可以声明完整单次目标。绑定后的实际参数、开始/结束事件、准备记录、动作回执、磁盘历史和录制文件使用同一份目标。连接改变后不能复用旧连接的采证边界。
- Android 的物理设备占用键继续使用原 serial，已有未知结果占用不会因平台模型更新而被绕过。原生、Flutter、UIA 的动作执行仍由既有端口负责。
- Intent 的目标在创建时冻结；观察同时保留请求目标与实际观察目标。安装/权限工作流使用同一合同。权限的用户编号保留在 PackageManager 和请求核验证据中，不再事后修改通用目标。
- 新写入声明 `aab.execution-evidence/v1`。不可变旧归档按原格式核验，不添加平台、不改原校验值，不作为新执行输入使用。派发前拒绝也有失败事件与录制结果，Host 调用 ID 为 null，不产生观察证明。
- 当前公开示例、维护中的验证控制器和发布文档同步到显式目标。iOS/Web 数据模型可表达，但执行入口仍明确拒绝，直到各自设备绑定、期限、取消和原结束凭据接通；本批没有宣称跨平台执行已完成。

## 方向与退出条件

之前的问题是验证范围收口不够明确，已经改为按能力缺口推进。当前目标模型的退出条件已经满足：输入、绑定、派发、占用和持久证据保持一致，错误在正确边界暴露，当前包可独立安装。

下一关是 iOS：先在接入设备上证明公开存查接口、原引用及真实进程重启，再接通 iOS 动作的设备/App 绑定、取消和未知结果恢复，最后开放最小 Intent/Script 同义流程。每个关口完成后冻结结果；只有新增代码影响原结论或出现新的反证，才重开相关验证。

Web、持续运行/资源指标、真实传输和最终四 App/整机组合验收仍在总计划中，不能由本批 Host 检查代替。后续工作不会继续扩展样例 App 功能来替代 Bridge 能力交付。
