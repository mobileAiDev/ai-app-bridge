## 对照条件

- 同一 Script SHA：`a45dff972a12e0281cc392f69595de7a781ba6f91e048e8901835d8cfe542006`。
- 同一 Host 代码 manifest SHA：`445aba4b2ffa5dbcf052ebdb37b523639effcceff7893ca9476a83b31d771600`；78 个文件涵盖执行代码及实际 native FactStore binary。
- 同一功能/场景清单、相同设备与 8 条初始笔记。每轮执行前的数据都与冻结 fixture `d90baa03-191e-43d6-8d47-82a378f5b0e6` 做完整 canonical 比较，未忽略字段，差异为空。
- 原架构 APK：`4e4122353e3c821bf4a5622ded960a4ed5dab9ed563e25f962574b8baf7b0afb`；迁移 APK：`8252b6c0a4d36ce1a38c4056ba2bb5becfa63ca18803e7dde42de3116cb80836`。每轮从设备读取安装的 base APK，核对真实字节 SHA。

原架构 APK 带较早一版已修复 IME 输入的 SDK；迁移 APK 另含更严格的输入目标保护。因此这组结果用于判断固定业务行为是否保留和套件实际耗时，不能推断单独的架构或 SDK 性能收益。也没有测量同等流程下 Agent 使用 Intent 的时间，不能计算 Intent vs Script 加速比。

## 证据和计时

每个页面检查点包含树、截图、第二棵树，与本轮 Host 发行记录、图片字节、Activity、时间和业务属性绑定。文字与标签必须属于同一笔记卡片；清单编辑状态按真实 Main/CheckedListView 及行属性验证。真实 checked 值、父子关系、项目顺序和勾选时间由独立 SQLite 读取确认。

三轮各自的 27 个 UI 检查点均重新独立计算通过；24 份数据库快照重新读取后与报告一致，每轮原有笔记都保留。R5 还独立复核了 436 份文件 SHA，以及 138 份持久 envelope 的读取和重开 checksum。这里的 envelope 为 dispatch-marker/action-receipt/checkpoint；81 份 UI 观察另按 payload SHA 和 Host 发行记录验证，不能混为一类。

计时包含 APK 预检、Script 操作与等待、截图/树、强停重开、数据库采集、独立结果判断及文件完整性核验。安装和 fixture 准备另行留档，历史探索、编写及调试不被估算进固定回归耗时。报告最终磁盘写入在计时结束后完成。

两次迁移版成功和一次原架构成功提供了重复运行证据，样本量不足以描述长期稳定性。5～10 分钟可以作为完整冻结业务范围的后续目标，当前一分钟级结果只对应上述核心套件。
