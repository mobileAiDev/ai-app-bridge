## 本轮修复及测试

- 批量赋予标签由多次 UI 记录覆盖改为一次应用服务命令、一次 Room 事务。提交时重新读取记录，校验全部笔记和待添加标签存在；未修改的 PARTIAL 标签合并到最新状态；第二条 SQL 失败时全部回滚。
- 删除同名标签引用时移除全部重复项。旧逻辑只移除首项，真实 Room 红测复现；这也是上游原有行为，不能归因于本次架构迁移。
- Host 原生摘要以前先输出背景设置页，64 KiB 裁剪可能把真正的前景弹窗截掉。改为先确定前景窗口再摘要，保留原始 sourceIndex；未知/禁用前景不退回背景。真实备份弹窗修复前后验证，3 项针对性测试、Host 全套 637/637 通过。
- 架构迁移让 ZIP 导入运行在存储操作的 IO 线程，原来的 `progress.value = ...` 在结束时触发 `Cannot invoke setValue on a background thread`。修复为 `postValue`；实际公开导入入口的失败收尾测试先红后绿，保证原始文件错误不被线程异常掩盖。真机再次删除后恢复验证了正常成功路径。
- 最终 candidate-v4 App **212/212** 测试通过；验证工具 **66/66** 通过。SQL 之后的广播等副作用出错不代表 SQL 回滚；SQL、偏好、附件不宣称断电原子性。

## 尚未关闭的边界

1. Intent provider 在启动时绑定原生 App，不能随 SAF 文件选择器自动跨包切换。本轮这些操作明确标为 inconclusive，并使用指定系统包 `com.coloros.filemanager` 的 Bridge UIA 完成。恢复返回 App 后重新启动 Intent；不声称备份全程只用了 Intent。
2. OPPO 文件名在 UIA 中含数字实体换行，现有精确文本点击未命中。本轮使用刚观察到的唯一文件节点中心点击；原始失败保留。后续需修复 XML 文本解码及跨包前景识别。
3. 全 App 分母继续保留 51 功能、143 模板、396 原子验收点、311 参数化变体。自定义三态、附件、加密、备份异常路径、完整置顶/颜色与其他功能尚未完整覆盖。
4. Script 计时只代表列明的固定回归范围，不包含 Agent 探索与写脚本时间，也不构成“全 App 已能在 5–10 分钟内测完”的证据。
