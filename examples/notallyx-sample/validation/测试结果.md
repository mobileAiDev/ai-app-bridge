本轮修复了三处实际问题：

1. Android Capture 当前周期查询扫描大量旧 payload，导致日志超时。现在以持久库附着时的明确 sequence 限定当前周期查询，保留显式历史查询。R9 操作后日志读取 24–484 ms；这是 9 次实测值，不是稳定性/P95 结论。
2. Script 历史把系统文件选择器调用归属到样例 App，导致独立 UI 证据被拒绝。现在按实际调用目标记录，生命周期仍属于 Script 本身。
3. App 导出把空音频 JSON 行数算作附件数。R9 看图发现“12 笔记、12 附件”与实际 0 附件冲突，视觉失败保留。candidate-v6 修复后，真机定向导出显示“10 笔记、0 附件”，ZIP 和全量数据库一致，57.200 秒完成补测；20 条新持久记录重开校验通过。

Host 测试 **647/647**，Android SDK **114/114**，App **212/212**，验证工具 **74/74**。v6 重新执行了 App 测试与受影响的导出流程；完整联合 R9 的身份、计时和历史 UI 缺陷仍属于 v5，没有混记到 v6。
